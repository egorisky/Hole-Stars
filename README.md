# Hole Stars

A top-down Unity game where a black hole moves around a scene and swallows objects,
growing as it consumes them. Built with the Universal Render Pipeline and targeting
Android as the primary build profile.

---

## Requirements

| Tool | Version | Notes |
|------|---------|-------|
| Unity Editor | **6000.5.1f1** | Must match exactly. A different version will upgrade the project files and force every other machine to upgrade too. |
| Unity Hub | latest | Used to install the exact editor version. |
| Git | 2.40+ | [git-scm.com](https://git-scm.com) — the Windows installer includes Git LFS. |
| Git LFS | 3.x | Required. Binary assets (models, textures, audio, fonts) are stored via LFS. |

Render pipeline: `com.unity.render-pipelines.universal` 17.5.0
Input: `com.unity.inputsystem` 1.19.0 (new Input System)

## Setting up on a new machine

**1. Install the exact editor version**

Open Unity Hub → `Installs` → `Install Editor`. If `6000.5.1f1` is not in the
main list, use the `Archive` tab and pick it from the Unity download archive.

**2. Clone the repository**

```bash
git lfs install          # once per machine, not per repo
git clone https://github.com/egorisky/Hole-Stars.git
cd Hole-Stars
```

If `git lfs install` is skipped, the binary assets will clone as small text
pointer files and Unity will fail to import them.

**3. Open the project**

Unity Hub → `Add` → `Add project from disk` → select the cloned folder.

The first import takes several minutes while Unity rebuilds the `Library/`
cache from scratch. This is expected and only happens once per machine.

**4. Re-authenticate AI tooling**

API keys and account credentials are intentionally **not** stored in this
repository. On each machine you need to:

- Sign in to Claude Code separately (`claude` → login).
- Sign in to your Unity account for `com.unity.ai.assistant`.

The `CLAUDE.md` file in the repo root *is* version-controlled, so agent
instructions carry over automatically.

## Project structure

```
Assets/
  3D/            Imported models (toy-cartoon-planets)
  GeneratedModels/  AI-generated meshes
  Materials/     EventHorizonRing, HoleFloor, HolePit
  Scenes/        SampleScene — the main playable scene
  Scripts/       Gameplay code (see below)
  Settings/      URP render pipeline assets, build profiles
  Shaders/       HoleFloor, HolePit (custom hole rendering)
  SoundEffect/   Music and SFX
Packages/        Package manifest and lockfile
ProjectSettings/ Project-wide configuration
```

### Gameplay scripts

| Script | Responsibility |
|--------|----------------|

| `VirtualJoystick.cs` | Touch input for mobile |
| `GameManager.cs` | Game state, scoring, session flow |
| `UIManager.cs` | HUD and menus |
| `SoundEffectPlayer.cs` | Audio playback |

## Daily workflow across machines

Because Unity scene and prefab files are large YAML documents that Git cannot
merge intelligently, **never edit the same scene on two machines without
pushing in between.** Follow this loop:

```bash
# before starting work
git pull

# ... work in Unity ...

# before switching machines or shutting down
git add .
git commit -m "Describe what changed"
git push
```

If a conflict does occur in a `.unity`, `.prefab`, or `.asset` file, resolve it
by choosing one full version (`git checkout --ours <file>` or `--theirs`) rather
than hand-merging — partial merges of Unity YAML produce corrupt scenes.

---

## Required editor settings

These are already committed in `ProjectSettings/`, but if you ever create a
sibling project, replicate them:

- `Edit → Project Settings → Editor → Asset Serialization → Mode` = **Force Text**
- `Edit → Project Settings → Version Control → Mode` = **Visible Meta Files**

Without these, Unity writes binary asset files and regenerates asset GUIDs per
machine, which breaks every scene and prefab reference on clone.

---

## What is not tracked

The `.gitignore` excludes `Library/`, `Temp/`, `Logs/`, `Obj/`, `build/`,
`UserSettings/`, and the auto-generated `*.csproj` / `*.slnx` files. All of
these are regenerated by Unity on open — do not commit them, and do not copy
them between machines.
